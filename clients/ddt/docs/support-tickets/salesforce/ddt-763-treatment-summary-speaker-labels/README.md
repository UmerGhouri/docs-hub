## 4. How it works (background)

The ticket assumed the AI summary was a field on the Treatment Call. In the code it is not. It is written by RingCentral's AI and only displayed on the Treatment Call:

```
Call is recorded in RingCentral
  -> RingCentral's AI (RingSense, or AudioAI) produces a transcript, summary and next steps
  -> RingCentral sends them to Salesforce as an event
  -> RC_AIInsightProcessor saves them on a Call_AI_Insights__c record
       (AI_Summary__c, AI_Next_Steps__c, Transcript__c), linked to the Call_Session__c
  -> TreatmentCallController reads the newest Call_AI_Insights__c with content for the
     Treatment Call's session, and the panel shows it
```

So Salesforce stores and shows the summary text as RingCentral returned it. Nothing in Salesforce decides which speaker is the client.

## 8. Step by step

For the next report of a wrong name in an AI summary:

1. Open the Treatment Call and note its linked call session.
2. Find the `Call_AI_Insights__c` rows for that session and read `AI_Summary__c` and `Transcript__c`. Check whether the transcript itself labels the speakers wrongly, or only the summary does.
3. Compare with the summary shown in RingCentral for the same call. If the text matches, Salesforce copied it faithfully and the error is in RingCentral's AI output.
4. Correct the record the staff reported, and record what was done in the ticket, including the spot-check of other calls.

## 10. Known limits

- **AI summaries are not verified.** Anything that reads the summary trusts RingCentral's speaker attribution.
- **The panel shows the newest insight with content.** If more than one insight row exists for a session, an older, corrected one is not the one shown.

## 11. Reuse for similar issues

**How to recognise one:** an AI summary, transcript or next-steps text names the wrong person or role, while the human-entered notes are right.

- **Find who wrote the text before looking for a bug.** Here the text is RingCentral's, and Salesforce only stores it.
- **Compare the transcript with the summary.** That tells you whether the speaker split or the summarising step went wrong.
- **Write the outcome in the ticket.** This one was closed with nothing recorded, which is why this page cannot say what fixed it.
